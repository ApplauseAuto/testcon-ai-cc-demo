Checkout test fixed: 10/10 runs pass with `--repeat-each=10`.

**Cause:** `pay()` waited only for `POST /api/payment`, which returns `202 pending`, then slept a fixed 2s and read the status once. The gateway takes 0.6–2.8s to confirm, so slower payments still showed "Processing payment…".

**Browser:** after clicking "Pay now", the POST returned `202` and the page showed "Processing payment…". It then sent four `GET /api/payment/{id}/status` requests, 500ms apart (~2s), before showing "Done." and the "Payment confirmed" box.

**Changes:**
- **`pages/checkout.page.ts`:** removed `waitForTimeout(2000)`. `pay()` now waits for the `GET …/status` response whose body says `status: "confirmed"`. I also removed `paymentStatusText()`, since nothing uses it now and it read the page once without retrying.
- **`tests/checkout.spec.ts`:** replaced the one-time read with retrying assertions, `await expect(checkout.paymentStatus).toHaveText(...)` and the same for `paymentConfirmed`, matching `cart.spec.ts`. Expected texts come from `test-data/checkout.ts`, and no timeouts changed.
